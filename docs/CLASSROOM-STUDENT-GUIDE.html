01　準備正確的 App 與資料夾

用自己的帳號登入可開啟本機資料夾的 Codex 客戶端。先看官方桌面 App 說明與Windows 說明，確認系統與處理器相容。免費帳號可以先測試；本課不要求申請 API key 或先購買訂閱。

下載老師提供的完整 classroom ZIP，全部解壓縮。保留隱藏資料夾，不要另裝全域整合版，也不要課前自行更新程式碼。

medical-journal-pptx-classroom/  ← Codex 要選整個資料夾
├── START-HERE.md
├── setup-macos.command        ← Mac 安裝

├── check-classroom-...        ← 安裝後檢核

這是路徑說明，不是電腦截圖。App 介面依版本不同；請以正確資料夾與實際成功回覆驗證。工具支援 Intel Mac，不代表官方桌面 App 必定支援同一硬體。

02　依你的系統安裝

Mac

Finder 進入教材根目錄，雙擊 setup-macos.command。

有執行權限問題時，先核對來源。在 Terminal 輸入 cd ，將根目錄拖進視窗，按 Return，再執行：

bash setup-macos.command

可能出現 Homebrew、管理員密碼或 Command Line Tools 安裝提示。受管制電腦請洽資訊人員。

Windows

檔案總管右鍵 ZIP →「全部解壓縮」，進入根目錄，雙擊 setup-windows.cmd。

預設走原生 Windows / PowerShell，不需要 WSL。放在自己的文件資料夾，不要放 Program Files 或唯讀磁碟。

Python 安裝後仍找不到時，關閉終端機與 Codex，重開後再次執行安裝檔。

安裝程式會準備相容 Python（建議 3.12；支援 3.11–3.13）、專案 .venv、Python 套件、LibreOffice、Poppler，並執行測試。安裝與登入需要網路；教材不是離線免安裝包。

不要關閉防毒、Gatekeeper 或繞過學校／醫院管理政策。不要為方便直接開啟全面存取權；只批准你理解且確實需要的操作。

成功標準：顯示 Installation complete，沒有未處理的錯誤。

03　第一關：雙擊本機檢核

MacWindows
check-classroom-macos.commandcheck-classroom-windows.cmd

檢核會執行 doctor 與虛構 PDF 的 smoke-test。不呼叫 Codex 模型，不消耗 Codex 額度。安全摘要放在 .skill-work/classroom-preflight.json，不保存原始個人路徑或帳號資料。

看到的結果意思與下一步
LOCAL_READY核心測試通過，選用工具也被找到；PDF 匯出尚未實測。繼續第二關。
LOCAL_PPTX_ONLY核心測試通過，但選用工具不完整；可先做 PPTX，PDF／部分預覽受限。
LOCAL_BLOCKED核心環境或 smoke-test 未通過；回報老師，不要一直重跑生成任務。
CODEX_UNVERIFIED人工驗證提醒，不是安裝失敗。繼續下一節。

Mac 檢核檔若被移除執行權限，可在根目錄終端機執行 bash check-classroom-macos.command。

成功標準：doctor 通過、smoke-test passed；帳號仍待第二關驗證。

只有 LibreOffice／Poppler 缺少時，不必把整個 Python 重裝。必要 Python 已存在的受限環境，可由老師依原 quickstart 的 skip-system 路線處理。

04　第二關：讓 Codex 使用同一個資料夾

桌面 App 選 Codex，開啟資料夾／新增專案並選取教材根目錄，再建立新任務（New chat）。若有環境選項，選 Local；Windows agent 選 Windows native，不要切到 WSL。按鈕文字可能隨版本改變。

先貼「只讀驗證」，不生成簡報

請先確認目前工作資料夾是否為 medical-journal-pptx-classroom 根目錄。
讀取 .agents/skills/medical-journal-to-pptx-classroom/SKILL.md。
回報 skill 名稱、本專案 Python 環境位置、示範 PDF 路徑及 outputs 位置。
請勿生成簡報、安裝套件、修改檔案或存取其他專案。
若讀不到任何一項，明確說明，不要猜測或宣稱成功。

再貼「本機執行驗證」

請在同一個專案根目錄執行本機 journal doctor：
macOS 使用 ./journal doctor；Windows 使用 .\journal.cmd doctor。
只做檢查；不要安裝或升級套件、不要生成簡報。
若需要批准執行，先說明這條指令；不要要求全面存取權。
回報實際執行結果；若沒有執行權限，請直接說明。

成功標準：回覆正確 skill 名稱，且顯示本機 doctor 的實際結果。這仍不保證額度足以生成整份簡報。

skill 選單沒出現時，可嘗試上面的直接讀檔入口，但仍須驗證本機執行能力。一般網頁聊天能讀 PDF，不代表能執行你電腦上的專案。

05　上課才開始：一篇 PDF、一個任務

$medical-journal-to-pptx-classroom

請使用 full 模式處理 sample-papers/classroom-demo-paper.pdf。
製作 40–55 張英文教學投影片，每頁附繁體中文講者備註。
明確標示文章及數據皆為虛構教學資料，不是真實臨床證據。
保留重要 Figures、Tables、panel labels 與正確影像灰階方向。
通過建檔前及建檔後 QA 後，將最終 PPTX 放在 outputs。
缺少 PDF 匯出工具時仍先交付 PPTX，並說明未完成的檢查。

來源 PDF → 讀文與圖表 → 影像比對 → 英文投影片＋繁中講稿 → 建檔前 QA → PPTX → 建檔後 QA

自己的 PDF 放到 sample-papers/，將提示詞改成實際路徑。真實論文不要沿用「虛構」標記，並須有使用授權且無可識別病人資料。本專案僅提供 full，沒有 lite 模式。

到 outputs/ 找成品。數字、研究限制、圖表及講稿仍需人工對照；QA 通過不是臨床認證。修改成品後，不要沿用修改前的 QA 宣稱。

中斷／額度不足後接續

請繼續同一個簡報任務，讀取 .skill-work 中對應這篇 PDF 的 run.json、
RUN_MANIFEST.md 與已產生的 deck_spec.json，先回報已完成及未完成階段。
保留正確的既有圖表與成品，從未完成部分接續，不要從頭重做。
通過 QA 後把最終 PPTX 放在 outputs；無法完成的項目請明確列出。
